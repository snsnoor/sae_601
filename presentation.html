🏠 Contexte
Pourquoi ce projet ?
Une question concrète : comment trouver une opportunité d'achat immobilier en France avec des données publiques ?
  • Cadre académique — SAÉ 6.01, BUT Sciences des Données, IUT Laval, année 2025-2026.
  • Problématique — Les données DVF (Demandes de Valeurs Foncières) sont publiques mais brutes : valeurs aberrantes, natures hétérogènes, adresses non géocodées.
  • Objectif — Construire un pipeline ETL complet et un dashboard interactif permettant de comparer les communes, identifier les prix sous-évalués et qualifier la qualité de vie (DPE, bruit, école, transport).
  • Périmètre — Sélection par département(s) et année(s), données entièrement téléchargées via API open data.
  • Utilisateur cible — Un particulier cherchant à acheter un bien, ou un analyste immobilier comparant des marchés locaux.
Données 100 % publiques
Toutes les sources utilisées sont open data : DVF (data.gouv.fr), DPE ADEME, INSEE, SNCF, Éducation nationale, IGN.

🖥️ Infrastructure
Stack technique
Choix délibérément légers : pas de serveur distant, base embarquée, zéro cloud obligatoire.
🗄️
DuckDB — base analytique embarquée
Un seul fichier info_appart.duckdb. Requêtes SQL OLAP en mémoire, extension spatiale (ST_Distance, ST_Transform), lecture directe de CSV.gz distants sans téléchargement préalable, union_by_name pour fusionner des schémas légèrement différents entre départements.
🌐
Streamlit — interface web réactive
Pas de framework front-end séparé : Streamlit expose un serveur local (localhost:8501). Session state pour la navigation inter-pages. CSS injecté pour une charte graphique totalement personnalisée.
📡
Sources accessibles via HTTP
Toutes les sources sont interrogeables sans authentification. Les fichiers DVF sont des CSV.gz pré-compilés par data.gouv.fr (un fichier par département × année). DPE, gares, écoles, communes : APIs JSON paginées. INSEE : fichiers Excel/CSV statiques.
🐍
Python 3.12 · environnement Anaconda
Pas de conteneur requis. Le projet tourne directement dans un environnement conda. Le fichier requirements.txt liste les dépendances. Chargement de l'extension spatiale DuckDB automatisé à l'initialisation.
Déploiement : python launcher.py --departements 53 puis python download_data.py puis python init_base.py puis streamlit run Dashboard/front.py

🔎 Données DVF
Comment on sélectionne les lignes DVF
Trois niveaux de filtre successifs — du fichier brut au score final.
Niveau 1 — Ingestion (init_base.py)
Sélection des vraies ventes
  • valeur_fonciere IS NOT NULL — prix obligatoire.
  • nature_mutation IN ('Vente', 'VEFA') — on exclut les échanges (pas de prix de marché), adjudications (enchères = prix atypiques), terrains à bâtir (fausseraient le €/m²).
Niveau 2 — Nettoyage des NULLs
Remplissage défensif
  • Colonnes numériques (surface_reelle_bati, longitude…) → remplies avec 0.
  • Colonnes texte (type_local, code_postal…) → remplies avec 'NR'.
  • code_commune zero-paddé sur 5 caractères pour les jointures INSEE.
Niveau 3 — Requête dashboard
Filtres à la volée
  • surface_reelle_bati > 0 et valeur_fonciere > 0
  • type_local IN ('Maison', 'Appartement') — pas les locaux commerciaux, parkings, caves.
  • HAVING nb_ventes ≥ 10 — seuil statistique : pas de score sur 2 ventes.
⚠️ Conséquence sur le nombre de lignes : le DVF brut contient TOUTES les mutations (terrains, locaux commerciaux, échanges…). Après filtre, on conserve environ 30-50 % des lignes selon le département. Le HAVING ≥ 10 ventes agrège ensuite par commune — une commune avec 3 transactions n'apparaît pas dans les scores.

📊 Visualisation
Choix des graphiques
Chaque type de graphique est choisi pour la question qu'il répond, pas pour l'esthétique.
Spatial
Choroplèthe communal
Répond à "où sont les communes les moins chères ?" — la couleur encode le prix médian, la géographie révèle des gradients (centre-ville vs périphérie) invisibles dans un tableau.
Spatial
Scatter map (points)
Quand les communes sont peu nombreuses, les points permettent de localiser chaque vente précisément. En mode zoom, on voit les micro-variations intra-communales.
Comparaison
Barres horizontales
Comparaison des prix médians entre communes ou entre types DPE. Axe Y lisible même avec des noms longs. Tri par valeur décroissante pour un ranking immédiat.
Temporel
Courbe linéaire
Évolution mensuelle des prix sur 2024-2025. La continuité de la ligne rend les tendances (hausse, baisse, saisonnalité) plus lisibles qu'un bar chart temporel.
Score
Jauge semi-circulaire
Le score d'opportunité est une valeur entre 0 et 1 — la jauge communique instantanément si une commune est "bonne" ou "mauvaise" sans que l'utilisateur lise un nombre.
Corrélation
Scatter plot
Relation revenu-médian × prix €/m² ou DPE × prix. Le nuage de points révèle les outliers (communes atypiques) et le sens de la corrélation sans présupposer sa forme.

🐛 Obstacles
Problèmes rencontrés
Les bugs les plus formateurs — et comment on les a résolus.
  • urlretrieve silencieux sur 404 — data.gouv.fr peut renvoyer une page HTML en réponse à un département inexistant. Le fichier `.csv.gz` reçu était du HTML, jamais signalé. Solution : validation post-téléchargement (magic bytes gzip + détection HTML).
  • pd.NA incompatible float64 — pd.Series(pd.NA, dtype="float64") lève une TypeError avec les backends NumPy de Pandas. Remplacé par np.nan.
  • width='stretch' Streamlit — paramètre ajouté dans une version future, absent de la version installée. Remplacé par use_container_width=True.
  • code_postal inféré int vs str — selon le département, DuckDB infère le type de code_postal comme entier (53) ou chaîne. Résolu par ALTER COLUMN … TYPE VARCHAR avant tout remplissage texte.
  • Scores dégénérés — quand la colonne DPE ou PEB est absente, _minmax retournait 0.5 constant pour toutes les communes (facteur sans variance = pas de signal). Résolu avec une pondération adaptative : le poids d'un facteur dégénéré passe à 0 et les poids restants sont renormalisés.
  • Jointure DPE × DVF par adresse — les adresses DVF et DPE utilisent des formats différents ("r.", "av.", abréviations, accents). Résolu par une macro SQL normaliser_adresse() (strip accents, expansion d'abréviations, suppression ponctuation).
  • Colonnes DBF tronquées à 10 car. — le format Shapefile tronque les noms de colonnes. 'appellation_officielle' devient 'appellation'. Résolu par une détection multi-noms dans le code de lecture.

🏆 Points forts
Ce dont on est fiers
Les choix techniques qui font la différence.
🤖
Pipeline 100 % automatisé
Aucun fichier manuel : une commande lance le téléchargement de toutes les sources (DVF, DPE, INSEE, BAN, gares, écoles, communes). Le dashboard se charge seul.
⚖️
Score composite adaptatif
La pondération s'ajuste automatiquement si un facteur est absent (DPE, PEB, revenu). Les 3 facteurs restants absorbent le poids et le score reste comparable entre communes.
🎨
Charte graphique cohérente
CSS variables partagées entre le dashboard Streamlit et Plotly. Une seule modification du token --green-primary propage la couleur partout — aucune duplication.
🔁
ETL idempotent par département
Ajouter le département 35 ne détruit pas les données du 53 déjà chargées. Chaque couple (département, année) est géré indépendamment via DELETE ciblé + INSERT.
📍
Géocodage avec fallback BAN
Les ventes DVF sans coordonnées GPS sont géocodées via la BAN locale plutôt qu'éliminées. Cela préserve des dizaines de milliers de transactions supplémentaires.
🖥️
Mode démo complet
Toutes les pages du dashboard fonctionnent avec des données simulées reproduisant fidèlement la structure réelle. Permet de démontrer sans base chargée.

💡 Observations
Remarques intéressantes sur les données
Ce que les données DVF × DPE × INSEE révèlent vraiment.
×5
Amplitude des prix au sein d'un même département
Le prix €/m² médian peut varier d'un facteur 5 à 10 entre la commune la plus chère et la moins chère d'un département. L'effet "proximité centre-ville" est dominant.
F/G
DPE et période de construction corrélés
Les bâtiments construits avant 1975 (avant les premières normes thermiques RT) obtiennent massivement des étiquettes F et G. Ce signal est utilisable pour anticiper des travaux.
+12%
Premium "gare" mesurable
Les communes disposant d'une gare SNCF à moins de 2 km présentent en moyenne un prix €/m² supérieur de 8 à 12 % par rapport aux communes sans gare du même département.
15-20%
Part des VEFA dans les transactions
Les ventes en état futur d'achèvement (neuf sur plan) représentent 15-20 % des transactions retenues. Leur prix est systématiquement plus élevé de 15-25 % par rapport à l'ancien.
−8%
Décote PEB aéroportuaire
Les communes en zone de bruit aéroportuaire (plan PEB zones A-D) présentent un prix médian inférieur de 5 à 15 % par rapport aux communes comparables hors zone.
Avr–Juil
Saisonnalité marquée
Le volume de transactions culmine entre avril et juillet (printemps immobilier). Le creux est de novembre à janvier. Le prix médian suit partiellement ce cycle mais avec un décalage de 1-2 mois.
